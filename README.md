# Умный кредитный кабинет предпринимателя

MVP для хакатона «Альфа Будущее» (кейс Альфа-Банка). Сквозной путь от подбора продукта до выдачи: клиент подбирает кредит, заполняет заявку с автозаполнением по ИНН, даёт согласия, видит статус в реальном времени и понятные причины решения; банк разбирает серую зону в очереди аналитика.

> **Все данные синтетические. ФНС, БКИ, подписание и выдача смоделированы.** Подробности — в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

**Стек:** Python 3.12, FastAPI, PostgreSQL 16, SQLAlchemy 2 + Alembic, Jinja2 + HTMX, Docker Compose. LLM с открытыми весами (Qwen2.5 через Ollama) — по желанию, только для пересказа объяснения.

## Запуск

```bash
docker compose up --build
```

Откройте http://localhost:8000. Swagger: http://localhost:8000/api/docs.

При первом запуске контейнер `app` применяет миграции и загружает демо-данные (идемпотентно). Поднимаются: `db`, `fns-mock`, `bki-mock`, `app`, `worker`.

С LLM (скачает модель ~1 ГБ):

```bash
LLM_URL=http://ollama:11434 docker compose --profile llm up --build
```

## Сценарии проверки (T1–T10)

Все сценарии автоматизированы в `tests/test_scenarios.py`. Вручную в интерфейсе (под anna@demo.local, компания переключается в шапке):

| № | Как воспроизвести | Ожидаемо |
| --- | --- | --- |
| T1 | «Северный ветер» → Подбор → оборотный 1 000 000 ₽ на 12 мес. → финансы → согласия → отправить | Статус меняется на глазах, авто-одобрение → принять → подписать → «Выдан» |
| T2 | «Молодой старт» (4 мес.) → оборотный кредит | Отказ «Срок работы бизнеса» + другой продукт |
| T3 | «Долговой центр» → любая заявка | Отказ «Платёжная история» (действующая просрочка в БКИ) |
| T4 | Мария → KR-…-0002 → «На иных условиях» → 9 000 000 ₽ → Анна принимает | MANUAL_REVIEW → COUNTEROFFER → … → DISBURSED |
| T5 | Мария → «Запросить данные»; Анна загружает файл; Мария одобряет | MANUAL_REVIEW → NEEDS_INFO → MANUAL_REVIEW → APPROVED |
| T6 | Отказаться от предложения или дождаться истечения | OFFER_REJECTED или EXPIRED (истечение проверяет воркер) |
| T7 | Не отмечать согласие на БКИ | Кнопка отправки неактивна, API отвечает 422, запроса в БКИ нет |
| T8 | «Сбой связи» → любая заявка | Три попытки к ФНС, затем ручной разбор с пометкой «ФНС не ответил» |
| T9 | Двойная отправка; два аналитика решают одну заявку | Один результат; второй аналитик получает конфликт версии |
| T10 | Под elena@demo.local открыть `/applications/1` | 404 |

Ещё: «Закат» (ликвидация) — отказ по жёсткому стопу.

## Разработка без Docker

```bash
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt

# PostgreSQL должен быть запущен
export DATABASE_URL=postgresql+psycopg://kabinet:kabinet@localhost:5432/kabinet

uvicorn mocks.fns:app --port 8101 &
uvicorn mocks.bki:app --port 8102 &
alembic upgrade head
python -m app.seed
RUN_WORKER_IN_APP=true uvicorn app.main:app --reload --port 8000
```

`RUN_WORKER_IN_APP=true` запускает воркер внутри веб-процесса (удобно для разработки). В Docker воркер — отдельный контейнер.

### Тесты

## Структура

```
app/
  domain/        машина состояний и сервис переходов (единственное место смены статуса)
  services/      заявки, согласия, валидация, интеграции, скоринг, кредитная логика,
                 объяснения, аналитик, конвейер
  api/           JSON API + схемы (OpenAPI)
  web/           HTML-кабинеты клиента и банка
  templates/     Jinja2-шаблоны по макетам
  static/        CSS из дизайн-токенов макетов, htmx, шрифт Onest
  worker.py      воркер конвейера (outbox, SKIP LOCKED, истечение сроков)
  seed.py        демо-данные
mocks/           моки ФНС и БКИ (отдельные контейнеры), синтетические компании
migrations/      Alembic
tests/           pytest
docs/            архитектура, диаграммы, OpenAPI
```

## API

Документация: `/api/docs` (Swagger), спецификация: [`docs/openapi.json`](docs/openapi.json) — импортируется в Postman или Bruno как коллекция. Примеры запросов — [`docs/api.http`](docs/api.http).

Аутентификация: `POST /api/auth/login` ставит cookie сессии. Отправка заявки поддерживает заголовок `Idempotency-Key`. Ошибки в едином формате `{"error", "message", "details"}`.

## Настройки

Все параметры — переменные окружения, см. [`.env.example`](.env.example) и `app/config.py`. Основные: `DATABASE_URL`, `SECRET_KEY`, `FNS_MOCK_URL`, `BKI_MOCK_URL`, `LLM_URL`, `PIPELINE_STEP_DELAY` (пауза между этапами для наглядности демо), `FNS_FAIL_RATE` и `BKI_FAIL_RATE` (случайные сбои моков).

## Потенциал развития

- Заменить моки реальными интеграциями: контракт клиентов в `app/services/integrations.py` уже отделён.
- Откалибровать скоринговую карту на портфеле; новые версии модели — через `POST /api/admin/scoring-models`.
- Вынести конвейер и интеграции в отдельные сервисы по границам модулей; добавить брокер поверх outbox.
- Документооборот и реальная ЭП, приглашение коллег с ролями, уведомления.
- Шифрование чувствительных полей, rate limiting, SSO для сотрудников банка.
